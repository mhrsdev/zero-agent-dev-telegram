4 REAL BUGS FOUND & FIXED (all pinned by tests)
-----------------------------------------------
1) Webhook button presses were NEVER answered on the Bot API.
   The engine's webhook adapter holds no bot token (tokens are per-
   binding secrets), so the answer attempt died silently at _api_url.
   FIX: InterfaceTransportService.process_webhook answers the press after
   dispatch using the binding's resolved credential (outcome toast:
   "Plan approved" / "Plan rejected" / "Not allowed" / "Failed"), crash
   path included. Pins: test_webhook_press_answered_via_binding_credential,
   test_webhook_press_by_stranger_gets_no_credential_resolution.

2) One stale/expired callback query killed the ENTIRE polling worker.
   Telegram answers answerCallbackQuery with HTTP 400 QUERY_ID_INVALID
   for expired ids; that surfaces as a plain RuntimeError (not
   AdapterError) which escaped poll_forever's exception tuple.
   FIX: acknowledgement is unconditionally best-effort.
   Pin: test_stale_query_id_400_never_kills_the_polling_worker.

3) routing.primary_model never reached task execution / decomposition.
   The scheduler tick used settings.openai_model (gpt-4o-mini default).
   When your gateway stopped serving gpt-4o-mini (every task call
   edge-403'd while the aligned planner succeeded), approved plans could
   never execute. FIX: config_sync pins the scheduler tick to
   routing.primary_model (SchedulerService.set_tick_routing).
   Pin: test_config_sync_pins_scheduler_tick_to_routing_primary_model.

4) One transient CDN-edge 403 degraded every decomposition to the
   single-task fallback. FIX: the decomposer burns a bounded transport
   retry budget first (4 retries, 5/15/30/60s backoff); auth failures
   stay fail-fast. Pins: test_transient_edge_403_is_retried_not_degraded,
   test_transient_403_exhausting_budget_still_falls_back,
   test_auth_failure_stays_fail_fast.

4 个真实 bug（全部已修复 + pin）
--------------------------------
1) webhook 路径的按键从未被应答（webhook 适配器按设计不持有 bot
   token，应答在 _api_url 静默死亡）。修复：传输服务在 durable 派发后
   用 binding 解析出的凭证应答（含崩溃路径）。
2) 一个过期回调 query（HTTP 400 QUERY_ID_INVALID，普通 RuntimeError 而
   非 AdapterError）会杀死整个轮询 worker。修复：应答无条件 best-effort。
3) routing.primary_model 从未到达任务执行/分解（调度 tick 用
   gpt-4o-mini 默认值；网关停止服务该模型后所有任务调用 403）。
   修复：config_sync 把调度 tick 钉到路由表主模型。
4) 一次瞬态 CDN 403 就把分解静默降级为单任务回退。修复：分解器先烧
   有界传输重试预算（4 次，5/15/30/60s 退避）；认证失败仍快速失败。
