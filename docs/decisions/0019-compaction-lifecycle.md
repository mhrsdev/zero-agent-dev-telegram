# ADR 0019 — Compaction Lifecycle with Fit Ladder and No-Thrash Protection

- Status: ACCEPTED
- Date: 2026-08-08
- Milestone: 9 (Retrieval Router, Context Builder, Token Budgeting, Compaction)
- Skills applied: `zero-context-memory`, `zero-claude-token-economics`,
  `zero-recovery-consistency`

## Context

`PLAN.md` §14 (Milestone 9) requires:
- Compaction lifecycle with pre-flush, fit, summary validation, durable
  commit, atomic context replacement, and no-thrash protection.
- Compaction never replaces typed execution state or durable memory.
- Omitted material remains recoverable through immutable references.
- Failure between each durable compaction step leaves old context
  active or a complete recoverable new state.
- Repeated ineffective compaction stops with a typed blocker.

`zero-context-memory` §"Compact with a fixed degradation ladder": the
fit order is fixed: verbatim, oldest history removal, oversized
tool-result truncation, oldest current-step removal, newest-item
emergency truncation.

`zero-context-memory` §"Replace context only after durable commit":
the safe commit order is: memory transaction, transcript artifact,
execution snapshot, summary validation, provider-ready history, atomic
context pointer advance, audit event.

`zero-claude-token-economics` §"Prune deterministically before
summarizing": use a no-thrash guard after repeated compactions without
meaningful reclaimed space.

## Decision

Adopt a compaction lifecycle with:

1. **Pre-flush**: before compaction, the full conversation is stored as
   an immutable `transcript` artifact. This ensures the source material
   is recoverable even after the context is replaced.

2. **Fit ladder**: the conversation messages are fitted into the
   summarizer input budget using the fixed degradation ladder:
   - `verbatim`: if the messages fit, use them as-is.
   - `history_turn_selected`: remove oldest messages first.
   - `tool_truncated`: truncate individually oversized tool results.
   - `step_turns_selected`: remove oldest current-step turns.
   - `emergency`: hard-truncate the newest item.
   The rung used is recorded on the compaction record.

3. **Summary validation**: the summary must be non-empty and have a
   minimum length (10 chars). A real implementation would check for
   required fields (current goal, accepted decisions, modified
   artifacts, unresolved tasks, blockers, failures, next safe action).

4. **Durable commit**: the new context version is created with
   `active=False`. The compaction record transitions through states:
   `pre_flush → committed → activated`. The transcript artifact ID
   and summary are stored on the context version.

5. **Atomic context replacement**: `activate_context_version`
   deactivates all versions for the execution, then activates the new
   version. This is a single transaction; a crash leaves either the old
   context active or the new context fully activated.

6. **No-thrash protection**: if `NO_THRASH_MAX_CONSECUTIVE` (3)
   consecutive compactions do not reclaim meaningful space, the
   compaction is blocked with `CompactionThrashError`. The compaction
   record is stored with state `no_thrash_blocked`.

7. **Typed execution state preservation**: the `execution_snapshot`
   field on the context version carries the typed execution state
   (plan/task IDs, worktree IDs, etc.). This field is NOT generated by
   the summarizer; it is passed through from the caller. Per
   `zero-context-memory` §9: "The compaction summary is not allowed to
   be the sole copy of plan/task IDs and dependencies."

### Compaction record states

```
pre_flush → committed → activated
                    ↘ failed
pre_flush → no_thrash_blocked
```

## Rejected alternatives

- **Summarize without fitting**: rejected by `zero-context-memory`.
  The fit ladder ensures the summarizer input fits in the budget,
  preventing context overflow during summarization.
- **Delete old context versions**: rejected. Old context versions are
  retained for audit and rollback. Only the `active` flag changes.
- **Auto-retry on thrash**: rejected by PLAN.md M9: "Repeated
  ineffective compaction stops with a typed blocker." The caller must
  investigate the oversized source.
- **Summary as sole copy of execution state**: explicitly rejected by
  `zero-context-memory` §9. The typed execution snapshot is a separate
  field that survives compaction.

## Consequences

- Compaction is durable: the transcript is stored as an immutable
  artifact before the context is replaced.
- The fit ladder ensures deterministic behavior when the conversation
  exceeds the summarizer input budget.
- The no-thrash guard prevents infinite compaction loops.
- Typed execution state (plan IDs, task IDs, worktree IDs) survives
  compaction in the `execution_snapshot` field.
- Old context versions are retained for audit and rollback.
- Atomic context replacement ensures a crash leaves either the old
  context active or the new context fully activated.
