WHAT WAS FIXED (all verified end-to-end with real processes)

  $ZERO_HOME is) — the anchor file is never ignored again.

  every later start — from any directory — opens the same database.

HOW TO REPAIR YOUR MACHINE (Windows, in order)
----------------------------------------------
1. Extract the new code over your existing folder (or clone fresh):
     zero-agent-dev-telegram-fixed-20260829-v2.zip
   then, in that folder (PowerShell):
     pip install -e .[dev]

2. In the directory you USUALLY run zero from, run:
     zero doctor
   Read the report. Then apply the automatic repair:
     zero doctor --fix
   Expected output includes:
     [FIX ] pinned engine database to <path> in $ZERO_HOME/.env
     [RECHK] ok: telegram bot token=ok, provider ... api key=ok
     verified: every secret reference now resolves — run 'zero restart'

   NOTE: if `zero doctor` was run before, run it again AFTER installing
   this version — the scan is much smarter now.

3. Restart the service and verify:
     zero restart
     zero doctor
   "telegram ... bot @<yourbot>" and "secret-references ... all N
   reference(s) resolve" should be [ OK ] now.

4. Test in Telegram: send /start to your bot in your group.
   You should get: "Zero is online and this chat is linked. ..."
   (If the group was never added, run:
     zero telegram groups add --chat-id <your group id> )

5. If doctor cannot find a database that holds your secrets (you may
   have deleted the old one), either:
     a) re-run `zero setup` and enter your credentials again, OR
     b) set them once from the environment and let the engine store them:
          $env:ZERO_TELEGRAM_BOT_TOKEN="<your token>"
          $env:ZERO_OPENAI_API_KEY="<your key>"
          zero restart
        (they are stored encrypted; the env vars can be removed after)

RUNNING TWO INSTANCES (zero start + zero-develop serve --port 8001)
-------------------------------------------------------------------
That is fine now. The FIRST instance owns Telegram polling; the second
logs "another Zero process (pid N) is already long-polling this bot
token — this instance skips Telegram polling" and simply serves its
HTTP port. Only ONE instance may poll one bot token — this is a
Telegram platform rule, not a Zero limitation.
