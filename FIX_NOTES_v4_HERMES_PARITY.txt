WHAT WAS DONE SINCE v3
----------------------
1. HERMES-PARITY OVERHAUL (commit ea051da). The hermes-agent codebase was read
   end-to-end for everything messaging-related (Telegram gateway, long polling,
   sessions, foreground/background workers, media, reply anchoring, plan cards).
   Gaps found in Zero were fixed to Hermes parity:
   - media/document intake on Telegram (photos, documents, voice) — handled
     without crashing, content downloaded via getFile, echoed into the agent
     context;
   - reply anchoring: replies go to the originating chat/thread; if Telegram
     rejects the reply anchor (400, thread-not-found) the chunk is re-sent
     without it — the message is NEVER lost;
   - plan cards with inline buttons (approve/decline) delivered to the real
     group, approved via callback tokens;
   - conversational chat bridge: non-actionable messages now get a real LLM
     chat answer (previously silently dropped);
   - web_search tool wired at boot and granted to the main worker;
   - long-polling budget + heartbeat watchdogs for the polling worker.

2. TWO NEW LIVE BUGS FOUND DURING THE HARDEST-LEVEL PASS (commit 55ee64e):
   a) SSE-ONLY GATEWAY. Your gateway (api.justwoker.icu) answers every
      chat/completions request that declares TOOLS with text/event-stream
      chunks, even when streaming was NOT requested. The planner (no tools)
      got clean JSON, but every conversational reply with granted tools died
      with "provider returned invalid JSON". FIX: the adapter now aggregates
      the SSE stream (text concatenated, tool calls merged by index, last
      usage/finish_reason win). Hermes reference: anthropic_adapter documents
      the same SSE-only gateway class. Proven live: real SSE body → clean
      answer, finish_reason=stop, usage 87/814.
   b) MCP RESTART CRASH. On a reused database, every engine boot re-registered
      MCP tools and hit ToolAlreadyExistsError. FIX: registration is now
      idempotent — existing tool rows are refreshed in place.

3. E2E INFRA. scripts/run_round5_e2e.py runs the WHOLE real-credentials E2E
   (fresh setup → real engine on :8010 → 16 phases → teardown) as one command;
   the driver resolves live ids from the engine DB; the operator identity is
   pre-linked deterministically (real group members were racing the one-shot
   auto-link bootstrap).

WHAT TO DO ON WINDOWS
---------------------
1. Replace your local repo with this package (or pull once you grant push
   access — commits 30c18e8, 24903ff, b0e3889, ea051da, 55ee64e are ready).
2. pip install -e .        (first time already done? skip)
3. zero start              → production engine (honors config.yaml port)
4. zero-develop serve --port 8001 → dev engine, separate DB
5. zero logs               → you WANT to see:
       config sync: created telegram binding for chat -1004406039396
       polling:...: Telegram bot online: @SandboxEnvironmentBot (id=8753924431)
6. If api.telegram.org is filtered on your network:
       set ZERO_TELEGRAM_PROXY_URL=socks5h://127.0.0.1:1080     (cmd)
       $env:ZERO_TELEGRAM_PROXY_URL="socks5h://127.0.0.1:1080"  (PowerShell)
   then restart `zero start`. Everything (polling + outbound + doctor probes)
   goes through the proxy; DNS resolves through it too (socks5h).
